# ADR-0013: 入站发送者占位文案保持引擎内嵌缺省（不作运行时设置）

日期：2026-09-20
状态：已接受

## 背景

入站事件里发送者无法解析时（裸通道 id、HTML 剥除后无文本等），ingest 以
占位文案 `UNKNOWN_CUSTOMER_TEXT = "（未知客户）"` 落库，替代裸 id。
架构评审（2026-09-20，第 1 轮）指出该文案是业务 flavored 的中文缺省，
按 ADR-0011「业务缺省由产品仓部署种子提供」，建议改为运行时设置。

## 决策

**保持引擎内嵌缺省，不改为运行时设置。**

理由：

1. **同步链路约束**：占位替换发生在入站事件净化的同步函数内
   （`sanitizeInboundContent`），而运行时设置读取是异步（DB + 缓存）。
   把净化链路异步化牵连 ingest 主路径，回归风险大于收益。
2. **占位文案是平台可靠性机制的产出，不是业务策略**：它与「不丢消息、
   不落裸 id」的 ingest 兜底语义绑定，类似错误码文案而非话术。
3. **历史消息不可变**：占位文案已落库的历史消息不会因设置改变而重写；
   改成设置会制造「设置只影响新消息」的隐性分叉。

## 后果

- `UNKNOWN_CUSTOMER_TEXT` 保留在 `conversations/application/ingest-channel-events.ts`，
  注释指向本 ADR；评审不再将其计为引擎/业务边界违规。
- 若产品未来要求可配置占位文案（多语言部署等），应连同历史消息展示层
  一起改（展示时替换，而非落库时），届时重新开 ADR。
- 通道 wire 类型编号（1/3/34/43/49）与裸 id 形态正则已同批归位
  `modules/channel/contracts/channel-wire.ts`（通道契约层所有）。
