# 01 · 产品概述

> 事实基线：`weflow` 仓 `main` 分支 LLM_v1.2.0_D9.28（2026-09-28）。
> 出处以括号内路径标注。

## 1. 产品定义

**Weflow 是一个「单进程部署、配置集中、可高效热更新的 AI 客服产品」**（根 `CONTEXT.md`）。

它解决的核心场景：企业通过**微信**（私聊 + 群聊）接收客户咨询，由 AI（大模型 Agent）
7×24 自动接待——查知识库、看图片、听语音、维护长期记忆、按约定定时回复；
遇到高风险/复杂问题时**自动转人工**，客服在网页端/桌面端/手机端**接管会话**，
处理完交还 AI。全程**可审计**（每轮决策、每次模型调用、每次人工操作都有事件留痕）。

三条产品级卖点：

1. **单进程部署**：一台 Windows 机器即可跑全栈（api + 两个 worker + PG + Redis + 微信通道），
   前端由 api 进程静态托管，无独立前端服务器。
2. **配置集中**：模型、知识库连接器、群聊策略、行为参数、全局开关——全部在网页端
   「设置中心」维护，**热生效**（30s 内），不改配置文件、不重启进程。
3. **高效热更新**：前端整包替换秒级生效、用户无感知；后端只滚动重启两个 worker，
   api（HTTP 入口）零中断；进行中的 Agent Turn 由队列与数据库状态机接管断点恢复。

## 2. 明确「不是什么」（已退役的世界观）

以下机制**已整体退役**，文档与代码中不应再出现（根 `AGENTS.md` §4）：

- ❌ 没有方案市场、没有微前端（ExtensionHost / `consoleExtensions` / mount 契约 / memory history 均已删除）。
- ❌ Console 平台壳已退役冻结：仅保留登录/改密/审计/用户/系统状态等平台页面维护，**禁止新增功能**。
- ❌ 不再有 solution store / registry / runner / npm-market / signature / lock；
  插件加载 = `WEFLOW_PLUGIN_DIR` **目录直读**，无打包/安装/激活/回滚流程。
- ❌ 「平台 + 多 Solution」双层世界观已退役；不为假想的「第二个产品」做架构预留。
- ❌ Console 不承载任何业务 UI（客服工作台、会话页等只存在于 support-web）。

## 3. 用户与角色

| 角色 | 是谁 | 入口 | 能做什么 |
|------|------|------|----------|
| **End User（客户）** | 微信上的外部联系人，**不是登录用户** | 微信私聊/群聊 | 正常聊天；可被拉黑/设为仅人工 |
| **operator（客服）** | 管理员发放账号的内部人员 | support-web / 桌面端 / 手机端 | 看全部会话、接管/认领/转交/解决 Handoff、人工回复、管理联系人档案（含拉黑）、素材库、个人资料 |
| **admin（管理员）** | 同上，角色为 admin | 同上 | operator 全部能力 + 用户管理、审计、系统状态、设置中心（模型/知识库/行为/群聊策略）、AI 员工配置、联系人策略页 |
| **工程师/运维** | 内部 | weflowctl CLI、服务器 | 部署、热更新、体检、排障（见 13 章） |

账号体系：用户名+密码（argon2id 哈希），管理员建号后 `must_change_password` 强制改密；
Web 端 Cookie 会话（默认 12h），手机端不透明 Bearer token（30 天长时效 + 滑动续期）。
登录限流：10 次失败 / 15 分钟窗口，双维度计数（IP+用户名 与 纯 IP）。

## 4. 功能地图（用户可感知）

### 4.1 客户侧（微信）

- 私聊 AI 自动接待：文本、图片（AI 识图）、语音（AI 转写）、文件、视频、表情包（文本化 `[表情包]<含义>`）、拍一拍。
- 群聊：@机器人触发（botNames 文本匹配，部署种子默认 `["客服"]`）；@ 命中开启「群聊线程」，
  线程存活期内（默认 15 分钟 TTL）任何群成员发言免 @；模型 `end_session` 自主收线或 TTL 到期收线；
  群噪声（纯表情/标点）在闸门处直接不建轮。
- 模型可做的 9 类决策：回复、追问、查知识库、调工具、**转人工**、不动作（10 种原因申报）、
  等待后自唤醒、结束会话、定时发送（联系人级开关，缺省关闭）。
- 联系人级策略（黑名单制，0078 起）：新联系人默认 AI 自动回复；可设「仅人工」或「拉黑」
  （拉黑 = 不建轮、不进列表、不推送，消息仍入库）。

### 4.2 网页端 / 桌面端（support-web，产品唯一网页端）

- **会话工作台**（`/conversations`）：三区队列（等待处理/我处理的/其他对话）、微信式消息气泡、
  回合侧轨 TurnRail（ChatGPT 式 minimap）、「AI 正在思考」胶囊、决策轨迹抽屉（27 类事件时间线、
  思维链折叠）、右侧上下文检查器（轮次体检/交接简报/回答依据/客户资料/历史对话五视图）。
- **人工操作**：认领/接管/转交（转客服或专业队列）/解决/收尾、人工回复（文本/图片/文件/素材/
  引用回复/@提及/表情）、拍一拍、发送结果查证（unknown 必查）、定时任务全局管控面。
- **知识工作区**（`/knowledge`）：证据验证流 + 知识库只读浏览（数据经 Core 白名单代理访问 WeKnora）。
- **素材空间**（`/assets`）：图片/文件两类持久素材，上传即持有、搜索/改名/软删，发送复用不重传。
- **AI 员工**（`/ai-employees`，admin）：AI 客服人设的版本化管理（草稿→发布→回滚）+ 联系人绑定。
- **设置中心**（`/settings`，admin）六分区：AI 员工/模型/知识库/行为/安全/部署（详见 09 章 §6）。
- **平台页**：用户与角色、审计日志、系统状态、个人资料。
- 桌面端与网页端**同一套代码**（Tauri 壳加载 api 托管的同一 dist），桌面端额外有连接页
  （本机→公网自动探测、可改服务器地址）与「检查器默认收起」的窗口适配。

### 4.3 手机端（`@weflow/mobile` 0.9.0，Expo/React Native）

- 微信式双页横滑首页（会话页 | 联系人页）：需要处理（橙）→ 我处理中（蓝）→ Agent 处理中（灰）→ 普通会话；
  左滑隐藏会话；联系人通讯录。
- 会话详情：聊天记录、实时 SSE + 轮询兜底、Handoff 状态驱动底栏、人工回复（幂等 + 结果未知自动复查）、
  图片/文件/素材发送、语音播放 + 转写、引用回复、拍一拍、结构化 Brief（建议首句一键填入）、本地草稿。
- 推送（FCM/Expo Push）三类通知：有等待处理 / 转给你 / 我处理的会话有新回复；通知默认**不显示正文**（隐私）；
  角标只统计「需要立即处理」。
- 安全：后台隐私遮罩、SecureStore 加密存储、图片只进内存缓存不落盘、30 天会话 + 滑动续期。
- QQ 式多账号快捷登录（最近账号头像横滑 + 静默自动登录）；OTA 热更新（EAS Update）。

### 4.4 运维侧

- `weflowctl` CLI：`dev doctor|up|down`（七类体检 + 自动修复）、`service install|start|...`（WinSW 服务化）、
  `config`、`completion`。
- 系统状态页：服务健康（configuration × health 矩阵）+ 最近 Agent Turn 诊断表。
- 审计日志：登录、用户管理、Handoff 操作、设置变更、知识代理变更等全带操作者 + 源 IP。

## 6. 与同类产品的差异点（工程师视角）

- **不发微信 API**：微信通道是「直读本地加密 DB + UIA 界面自动化」的参考实现（个人微信可接入），
  通道与 Core 之间是**通道中立协议 v6**（`CHANNEL_PROTOCOL`，见 07 章），可替换为企业微信/飞书等适配器。
- **决策显式化**：模型每轮必须输出结构化决策（连「什么都不干」都要带 10 种原因码之一），
  每一轮都有可审计结局——这是产品「可审计」的根基。
- **吸收式回合**：客户在 AI 处理中插话不会打断重来，而是并入当前回合重新决策
  （`absorbVerdictFor` 三分裁决矩阵，见 06 章 §5）。
- **热更新是架构属性而非运维技巧**：前端 hash assets + index.html 不缓存；api 持有 HTTP 入口不动；
  worker 无状态断点恢复；设置三类存储（runtime_settings / extension_settings / model_registry）全热读。
