# 16 · 术语表与历史沿革

## 1. 领域词汇表（合并引擎层 + 业务层 + 工作区）

| 术语 | 含义 |
|------|------|
| Channel Host | 通道适配器进程；微信场景 = Python 进程，直读微信 DB + GUI 自动化；拥有通道传输事实 |
| Core | 无界面业务核心；拥有除通道原始事实外全部业务事实 |
| support-web | 产品唯一网页端（Vue 3 SPA，core-api 静态托管） |
| Conversation | 通道无关的标准化消息/处理状态/游标/发送结果集合 |
| Message | 会话中一条标准化消息；出站按 reply_segments 逐段成行（batch + sequence） |
| send operation | 出站发送的持久化单元（operationId 幂等）；Host 5 态 pending/executing/confirmed/unknown/failed |
| 发送状态 8 态 | `messages.send_state` 唯一权威（core `send-states.ts`）：pending/submitting/observed/confirmed/failed/unknown/held/cancelled（0080 CHECK） |
| Agent Turn | 一次触发的编排过程（决策/上下文/模型推理/工具执行）；trigger_message_id 唯一 |
| 回合（Episode） | 首次触发到机器人自主收口（wait 交权 / end_session / 预算）的连续服务过程 |
| 回合吸收 | 客户插话并入当前回合；排队旧轮 superseded(absorbed_into)；三分裁决矩阵 |
| 会话事实卡（Fact Card） | 每会话一份 JSONB 当前状态（问题/已确认事实/已尝试/承诺/待确认），决策时全量更新 |
| 轮窗（Round Window） | 20 条原文外更早回合的摘要行（≤4 行、72h），从精确落库轮次重建 |
| 群聊线程（Group Thread） | @ 命中开启的话题单元（`session:group-thread:`）；存活期内免 @；end_session/TTL 收线 |
| Session Wake | wait 决策的持久化自唤醒计时器 |
| Triage | 主决策前的极速小模型分流（人工/自动 × 简单/标准）；fail-open |
| Execution Profile | 决定会话是否/如何运行 Agent 的执行配置（max_model_calls=2 / max_tool_calls=1 / 60s） |
| Execution Strategy | 业务插件注册的策略：buildModelRequest / parseModelResponse / validateAction；不得直接调模型/DB/通道/工具 |
| Skill | 业务插件的技能注册（SkillRegistry 机制在、允许空置） |
| Handoff | 人工接管状态机（pending/in_progress/transfer_pending/resolved/finished）；会话级暂停；归属锁 |
| Memory | 跨轮提取的长期事实/偏好/关系（12 条召回；90s 安静窗口提取） |
| Knowledge | 经摄入、索引、可追溯检索的外部资料（WeKnora；证据可归因） |
| KnowledgeEvidence | 检索证据（chunkId/title/content/matchedContent/score） |
| Media | mediaId 引用的非文本内容（元数据/派生/访问/保留期在 Core；字节在文件存储） |
| Asset | 素材空间持久条目；发送按「素材+会话+clientRequestId」确定性派生 mediaId 不重传 |
| Contact Profile | 联系人档案：备注/标签/别名/agent_enabled/scheduled_send_enabled/blocked |
| agentEnabled | 黑名单制自动回复开关（0078 起默认 true）；false = 仅人工 |
| blocked | 拉黑：不建轮/不进列表/不推通知（消息仍入库） |
| chatType | 会话类型事实 private/group（协议 v6 上报，ingest 落库一次） |
| WECHAT_ACCOUNT | 多账号隔离（ADR-0005）：host 实例只服务该账号 |
| channel_account | 联系人/会话的账号维度（默认 default） |
| source checkpoint | Host 每会话水位（sort_seq），增量捕获 |
| historical | 回溯合成事件标记：照常入库、零副作用 |
| 部署种子（product seed） | BFF 注册时幂等写 extension_settings 的业务缺省；只补缺不覆盖 |
|Kill Switch| runtime-settings 的「AI 自动应答」总开关（瞬时暂停新 AI 回复） |
| Turn Admission | 入站合并窗口（12s/半句 30s），CAS 认领建轮 |
| 工具租约 | tool_executions.lease_until 5 分钟；过期恢复重领 |
| 归属锁 | `pg_advisory_xact_lock("weflow:ownership:<conversationId>")`——人工与 Agent 出站互斥 |
| reply_segments | 模型回复分段（≤8 段 × ≤500 字）；逐段独立消息发出（打字节拍） |
| 发送期插话闸门 | 每段发出前检查新入站；命中 → 剩余段落 held + reply_interrupted（ADR-0012） |
| 事实卡/轮窗/长期记忆三层 | 见 06 章 §6 |
| SSE 失效信号 | 事件只作失效信号非事实来源；消费端回拉权威状态（ADR-0009） |
| 会话新鲜度控制器 | support-web `use-conversation-realtime.ts` 的机制模块名（业务词汇表） |
| Handoff 展示词汇表 | `handoff-vocab.ts`——Core Handoff 多方言到 UI 单一词汇的唯一投影点 |
| 决策协议 | 插件 `decision-protocol.ts`：8 值动作 + WAIT_MS 边界 + 工具清单（Core 9 值契约的业务子集） |

## 5. 错题本精粹（`weflow/docs/error-log.md` + 各 PLAN 的教训）

| 教训 | 预防机制 |
|------|----------|
| create-user 打印密码只显示一次且与哈希不匹配 → 全页 401 | create-user 加验证步骤、reset-password CLI、迁移后登录 smoke |
| 前端调用了未注册的后端路由 → 404 | 前后端契约检查 + API 契约差集测试 |
| tsx watch 子进程崩溃不自动重启 | `start-dev.ps1`（自动 Load-Env）+ weflowctl dev up 托管 |
| 8s 歧义对账窗口必然超时（微信写库滞后 ~11s） | 窗口 30s + 每 1s 轮询 |
| GUI 发送卡死拖垮整个宿主（OCR 38 分钟） | 发送墙钟超时 180s + OCR 硬超时 12s + 挂起探针 |
| undici FIN 断言崩进程 | responseBodyStream 8MB 预读缓冲 |
| dispatcher 每秒重投非 inbound 媒体 | terminalize-non-inbound-media |
| 「同几句话换序再说」绕过复读判定 | replyFingerprint 顺序无关指纹 |
| 视觉模型偶发丢 next_action 键 → 整轮静默 | 提示词硬性一行示例 + parser 兜底（夹带文本按 reply 发出） |
| 旧 AI 员工提示词无输出契约 → 丢字段 | 两路径统一注入输出格式块（机制块不带风格） |
| OTA 指纹被 up-to-date 旧文件烤进 APK | 发版前 runtimeversion:resolve 与 fingerprint 文件核对 |
| frpc 继承开发代理变量死循环 | frpc-start.ps1 先清六个代理环境变量 |
| `model_output_truncated` 静默放行 | finish_reason=length → 降上下文重试一次 → 转人工 |
