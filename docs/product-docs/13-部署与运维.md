# 13 · 部署与运维

> 出处：`weflow/docs/deployment-guide.md`、工作区 `docs/ops.md`、`x230-deploy/*`、
> `tooling/weflowctl/`、`deploy/`。

## 1. 两种部署形态（同一产品）

| | 开发（本机） | 生产（X230） |
|---|---|---|
| 进程 | tsx 直跑源码 + watch（`weflowctl dev up`） | node 跑 `dist/`，服务托管 |
| 服务包装 | 无（dev-pids.json 托管记录） | **NSSM**（`weflow-api` / `weflow-agent-worker` / `weflow-ingestion-worker` / `weflow-postgres` / `weflow-redis`）——仓内标准路径是 **WinSW2**（`weflowctl service`），X230 是 NSSM 历史形态 |
| 前端 | Vite dev server 5174 | api 静态托管（3100 同源） |
| .env | `core/.env` | 同一文件（`NODE_ENV=production`） |
| 日志 | `core/.dev-logs/` | WinSW: `tools/winsw/logs/`；NSSM/X230: `C:\We\logs\` |
| 公网 | 本机 frpc（web 指 5174） | X230 frpc（web 指 3100，onstart SYSTEM 计划任务） |

**两模式勿混跑**（会抢 3100/3101 端口）；切换前先 `dev down` 或 `service stop`。

## 2. weflowctl CLI（`tooling/weflowctl`，零运行时依赖）

| 域 | 命令 | 作用 |
|----|------|------|
| dev | `doctor` | 只读体检七类：env 必需键 / Postgres（TCP + 业务表确认）/ Redis / 5 服务（端口归属→身份匹配→探针→**陈旧度**：源码 mtime 晚于进程启动 = stale）/ 状态机（pass/stale/probe_failed/not_running/**foreign_owner**/unknown_owner）/ Channel 协议对齐（capabilities vs contracts 权威）/ 汇总 |
| dev | `up` | doctor + 自动修复：缺表自动迁移（幂等 180s 超时）→ 逐服务拉起/重启陈旧 → 采纳孤儿实例（端口反查真实监听者 PID 登记）→ 复检；channel-host 需要时自动 UAC 提权 |
| dev | `down` | 按 `core/.dev-logs/dev-pids.json` 停全部托管进程 |
| service | `fetch-host` / `install` / `uninstall` / `start` / `stop` / `restart` / `status` | WinSW2 v2.12.0 包装三进程（`weflow-core-api` 等 Windows 服务名）；XML：延迟自启 + 崩溃重启 10s/30s 两次后放弃 + 1 小时重置 + 日志 10MB 滚动留 8 份 |
| config | `get/set/list` | 本地 CLI 配置 `~/.weflow/config.json`（敏感打码） |
| completion | `bash/zsh/powershell` | 补全脚本 |

dev 服务定义五项：core-api(3100, `/health/ready`)、agent-worker(3101)、ingestion-worker(3102)、
channel-host(43123, `/healthz` **accept401**，elevated)、support-web Vite(5174, key 仍叫
`console`——兼容旧记录)。

## 3. 从零部署（生产，`deployment-guide.md` 十五步精要）

1. 环境要求：Windows Server 2019+/10/11、Node >=24 <25、pnpm >=10、Git、PG16、Redis 7、
   微信桌面 4.1.12+（关自动更新）、Python 3.12 + uv（仅通道）。
2. 基础设施：`docker compose -f deploy/compose.yaml up -d`（postgres:16 + redis:7）或本机安装。
3. 代码：clone → **先构建 `packages/contracts`**（core 类型别名指向其产物，否则 32 个
   Cannot find module）→ core / weflowctl install+build → `cd solutions && pnpm install:all`。
4. `.env`：copy `.env.production.example` → 填 `DATABASE_URL/REDIS_URL/MODEL_API_KEY/
   WEB_DIST_DIR/SESSION_COOKIE_SECURE/CHANNEL_HOST_*/WEFLOW_PLUGIN_DIR`。
5. 迁移与账号：`pnpm migrate:prod`（幂等）→ `node --env-file=.env dist/scripts/create-user.js
   admin --role=admin`（密码 ≥12 位只显示一次）；忘密码 `reset-password.js`。
6. 构建：core `pnpm build` → solutions `pnpm build`（插件先于前端）。
7. 服务化：`service fetch-host` → `service install`（管理员）→ `service start`。
   **Channel Host 不服务化**：`uv venv .venv && uv pip install -e . && uv pip install winsdk
   pypinyin`；计划任务 `schtasks /create /tn "Weflow-ChannelHost" /sc onlogon /rl highest`。
   （计划任务名两套口径：仓内 deployment-guide 用 `Weflow-ChannelHost`；X230 现役任务名是
   **`Weflow ChannelHost`**（空格，见 §5 与工作区 docs/ops.md）——在 X230 上操作以空格版为准。）
8. 验证：`/health/ready`（3100）→ `/health/live`（3101/3102）→ `curl 127.0.0.1:3100/conversations`
   返 SPA → 登录 200 且 Set-Cookie 无 Secure（局域网）→ 微信实测收发闭环。

X230 特有（2026-09-15 U 盘离线部署）：PostgreSQL 16 zip 版 initdb 注册服务 `weflow-postgres`；
Redis 用 tporadowski 5.0.14.1 Windows 移植注册 `weflow-redis`；`powercfg` 永不睡眠 +
netplwiz 自动登录（微信通道需要开机自动进桌面）；icacls 锁 `.env` 权限。

## 4. 热更新规程（核心卖点）

### 4.1 前端（无重启，秒级）
```powershell
git pull; pnpm --dir solutions/customer-support/apps/support-web build
Rename-Item <dist> dist.old   # 原子替换避免文件占用；随后删旧
```
原理：index.html 不缓存 + assets 带 hash 新旧共存 → 用户无感知不丢会话。

### 4.2 后端（api 不动，只滚动重启 worker）
```powershell
git log -1 --format=%H > C:\weflow\.last-good-commit   # 回退点
# contracts 有改动先 build contracts
pnpm --dir core build; pnpm --dir tooling/weflowctl build
cd core; pnpm migrate:prod; cd ..
weflowctl service restart   # 仅两个 worker；进行中 Turn 由队列+DB 状态机断点恢复
weflowctl dev doctor        # 体检
```

### 4.3 备份与恢复

- **数据库**：`pg_dump`（X230 有 `weflow-backup` 计划任务每日 03:00；docker 部署用
  `docker exec weflow-postgres pg_dump -U weflow weflow`）。任何含 migration 的更新前先手动做一次。
- **媒体字节**：媒体文件在磁盘 `FILE_STORAGE_ROOT`（X230 `C:\We\weflow\core\.data\files`），
  与 PG 元数据是**两份资产**——完整备份必须**同时**备库和该目录（可不一致：媒体行指向缺失文件时
  前端按 404 降级展示，不崩）。
- **恢复步骤**：① 停三服务（`service stop` / NSSM stop）→ ② psql 回灌快照
  → ③ 恢复文件目录 → ④ 起服务 → ⑤ `weflowctl dev doctor` 体检。
- **通道对齐**：channel-host 的 SQLite 事件库与水位**独立于 PG**，恢复后无需对齐——Core 侧
  `channel_cursors` 随库回灌到备份时点，Host 从游标之后继续增量；需要更早历史时用
  `POST /api/v1/admin/channel/sync`（historical 通道）幂等重扫。
- **磁盘满预案**：服务日志 10MB×8 自动滚动不会撑爆；增长源是媒体目录与 PG——监控磁盘，
  必要时先停 ingestion-worker（止血新媒体落盘）再归档。
- **保留策略与公网 TLS**：内置自动化只有「X230 每日 03:00 pg_dump 一份」；**保留份数/存放
  位置/异地副本/恢复演练周期由部署方制定**（建议：≥7 天滚动 + 破坏性迁移前手动快照 + 每季度
  演练一次回灌）。`*.leaif.com` 证书签发/续期在 **frps 服务器侧（38.22.235.27 的 caddy）**
  完成，属服务器侧运维、不在本仓范围；frpc 半边只做 TCP 隧道，不感知证书。

### 4.4 配置 / 插件 / 回退

- `.env` 改动 → `service restart`；设置中心改动 → 热生效无需重启。
- 插件 → build → restart；通道代码 → 重启计划任务。
- 回退：`git revert` 或 `git reset --hard $(cat .last-good-commit)` → rebuild → restart。

### 4.5 密钥轮换

| 密钥 | 轮换步骤 | 影响 |
|------|----------|------|
| `CHANNEL_HOST_TOKEN` | core `.env` 与 channel-host 环境两端同步改 → 重启 api 与 Channel Host | 短窗口内轮询 401，无数据影响 |
| `KNORA_ACCOUNT_ENC_KEY` | **轮换会使 `knora_accounts` 既有密文不可解密**（AES-256-GCM）——需清空该表后让用户重新 `knora/bootstrap` 代管开通 | 知识桥接需重新授权，其余功能不受影响 |
| `MODEL_API_KEY` 等 Provider key | 设置中心「模型」页直接改（存 model_registry，热生效）或改 `.env` 重启 | 无需停机（界面路径） |
| argon2 密码哈希 | 无需轮换（每密码独立盐）；忘记密码走 `reset-password.js` | — |

## 5. X230 生产机（补丁基线与部署正路）

- 机器：ThinkPad X230（i5-3320M）、`192.168.0.108`、Win10 LTSC 2021；代码根 `C:\We\weflow`。
- 运行 **commit `51e6780` 构建**（2026-09-15 部署）；**`.git` 已损坏——不要在那边 git pull
  或原地重建**；X230 访问不了 GitHub，文件一律 pscp 传。
- 核对方式：本地 51e6780 工作树构建与 X230 dist 逐字节一致（190/193 文件哈希，2026-09-20）。
- **打补丁正路**：
  ```bash
  git worktree add <dir> 51e6780   # 快照 + mklink /J 挂 node_modules
  # 改 .ts（或跑 x230-deploy/patch-snapshot-*.js 现成补丁）
  node node_modules/typescript/bin/tsc -p tsconfig.build.json
  # pscp 只传变化的 dist/**/*.js（连同 .ts 留档）→ C:/We/weflow/weflow/core/dist/
  Restart-Service weflow-api|weflow-ingestion-worker|weflow-agent-worker -Force  # NSSM，进程不换代码
  ```
- **微信通道部署**：`C:\We\weflow\weflow\runtimes\channel-host-wechat`，计划任务
  `Weflow ChannelHost`；当前团队库 **V1.3.0**（vendored wechatauto 1.2.4.1，2026-09-26），
  旧版本备份 `*.bak-20260926-*`。重启用 `x230-deploy/restart-host-x230.ps1`
  （**先按命令行杀 python 再 schtasks /run**——`/end` 杀不掉 detached 子进程）；健康 = 43123
  监听 + 无 token 401。进程列表一对 python（venv 启动器 + Python312）是正常父子形态非双实例。
- **校验工具箱**（`x230-deploy/`）：`crash-loop-check.ps1`（AssertionError 须早于最后一次
  Redis version 启动横幅）、`diagnose-stuck-media.js`（应返回 0 行非终态媒体）、
  `verify-final.js`（文件字节 + JPEG 魔数 + 描述长度）、`pipeline-status.js`、`requeue-media.js`、
  `db-query.js`（查库一律用 node + core 自带 pg 读 `.env`，**psql 从 PowerShell 传参会被改写**）。
- **已知坑**：plink 引号不可靠（复杂命令写 .cmd/.ps1 传；.cmd 必须 CRLF）；.ps1 不要带 BOM
  （PS5.1 按 ANSI 解析，只用 ASCII）；`SESSION_COOKIE_SECURE` 没清空会登录即掉。

> 注：v1.2.0 已把 X230 的两枚快照补丁（response-body 预读缓冲、非 inbound 媒体终态化）与
> 发送超时/OCR 修复固化进主干。**X230 升级到 v1.2.0 的路径**：X230 与主干已分叉多轮
> （51e6780 之后有接口层重构），不能继续混装补丁——正路是按 §3「从零部署」的构建/迁移/服务
> 重启流程做一次**整版本更替**（先 pg_dump 快照 + `.last-good-commit` 回退点），或继续停留在
> 快照补丁路线直到安排停机窗口。

## 8. 排障速查（跨文档汇总）

| 现象 | 检查 |
|------|------|
| `web.leaif.com` 打不开 | `frpc status`；本机开发时 5174 必须真在监听 |
| 服务启动即停 | err.log：端口被 dev 进程占用 / `.env` 缺键 / dist 未构建 |

| SPA 路由刷新 404 | `WEB_DIST_DIR` 未配或缺 index.html |
| 前端更新后仍旧页面 | Ctrl+F5；确认 dist assets hash 变化 |
| 微信收发不通 | 微信已登录未锁屏；Channel Host 在跑；两端 token 一致；43123 401=活 |
| 发送全部 unknown | 看通道 outbound 对账（baseline/歧义窗口）；`send_execution_timeout` 只意味着等不下去 |
| API 进程连崩 | undici paused-assert（已修：`responseBodyStream`）；`crash-loop-check.ps1` |
| 媒体全部不可见/空转 | 非 inbound 媒体终态化（已修）；`diagnose-stuck-media.js` 应 0 行 |

## 9. 开发环境最快上手（新工程师第一天）

```powershell
# 0. 前置：Node >=24 <25、pnpm >=10、Git、Docker（或本机 PG16+Redis7）
# 1. 依赖（顺序敏感：contracts 必须先建，core 类型别名指向其产物）
cd weflow
pnpm --dir packages/contracts install; pnpm --dir packages/contracts build
pnpm --dir core install
pnpm --dir tooling/weflowctl install; pnpm --dir tooling/weflowctl build
cd solutions; pnpm install:all; cd ..

# 2. 基础设施（开发库，账号/密码/库名均 weflow）
docker compose -f deploy/compose.yaml up -d

# 3. 配置：copy core/.env.example core/.env，填 DATABASE_URL/REDIS_URL/
#    CHANNEL_HOST_*/MODEL_API_KEY（其余模型键按需）

# 4. 迁移 + 建第一个管理员
cd core; pnpm migrate
node --env-file=.env dist/scripts/create-user.js admin --role=admin   # 需先 pnpm build
cd ..

# 5. 一键拉起（体检 + 自动修复 + 全部服务含 support-web@5174）
node tooling/weflowctl/dist/cli.js dev up

# 6. 验证：浏览器开 http://localhost:5174 → 用第 4 步密码登录（首次强制改密）
#    无微信通道时产品仍可用（纯平台模式 + 手动造数）；连真实微信需本机微信桌面登录后启动 Channel Host
```

不跑微信通道时的最小验证路径：`pnpm e2e:gate`（solutions/，需 `MODEL_API_KEY`）会种一条
测试会话并等 Agent 回复——见 15 章 §5。日常起停一律 `weflowctl dev up | doctor | down`，
**勿与 `service` 模式混跑**（抢端口）。
