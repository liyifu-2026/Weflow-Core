# 2272 · 加密狗未识别（蓝牙声学降噪软件启动失败）

> 状态：**待产品/售后负责人复核**。本文按 2026-09 的一条真实会话（客户报
> 「无法启动蓝牙声学降噪软件 / 错误代码 2272」）整理，术语与错误码含义需与该
> 产品的官方手册、驱动文档核对后再上线到知识库。
>
> 面向 Agent 检索的写法：每个分支都带「要客户回报什么」，便于逐步排查。
> 与提示词的硬约束配套使用：**一次只让客户做一件事，做完等反馈再给下一步。**

## 症状与错误码

- 现象：客户端启动失败，提示错误代码 **2272**。
- 2272 的解释：**加密狗未被系统识别 / 未与软件建立通信**（等价于「没找到加密狗」）。
- 关键前提：2272 与「有没有插加密狗」无关，插着也会报——要按下面的分支区分
  「狗没通电」和「狗通电了但没被认到」。

## 排查前必须问清的一件事

**加密狗上的指示灯亮不亮？**（只看灯，不做任何操作）

- 灯**不亮** → 走分支 A（供电/枚举层）。
- 灯**亮** → 走分支 B（枚举成功但通信/授权失败）。**不要**在灯亮的情况下
  让客户反复插拔同一个 USB 口；灯亮说明供电和枚举至少部分正常，重复插拔
  是无效动作。

## 分支 A：指示灯不亮

按顺序做，**每做完一步回报结果再进入下一步**：

1. 换一个 USB 口重插（台式机优先插**机箱后面**的口，不要用前面板、USB Hub、
   延长线、显示器上的口）。
   - 要客户回报：换口后灯是否亮；软件是否还报 2272。
2. 若仍不亮：换一根 USB 线（若该型号可换线）。
   - 要客户回报：换线后灯是否亮。
3. 若仍不亮：把加密狗插到**另一台电脑**上试。
   - 要客户回报：另一台电脑上灯是否亮。
   - 另一台也不亮 → 判定为加密狗硬件故障，转人工走换新（见「升级与转人工」）。
   - 另一台亮 → 回到原电脑，按分支 B 的第 1 步继续查系统侧（USB 控制器/驱动）。

## 分支 B：指示灯亮但仍然报 2272

灯亮说明已通电，问题在系统识别或授权通信。按顺序做：

1. **看设备管理器**：右键「此电脑」→ 管理 → 设备管理器 → 展开
   「通用串行总线控制器」「人体学输入设备」「其他设备」。
   - 要客户回报：有没有带**黄色感叹号**的项？它的名字是什么（例如
     「未知 USB 设备（设备描述符请求失败）」「HID-compliant device」）？
   - 有「未知设备 / 无法识别的设备」→ 先卸载该项，再「扫描检测硬件改动」，
     然后重新插拔加密狗。
2. **重装加密狗驱动**：用软件安装目录下的驱动安装程序（或安装包里的
   dongle/driver 目录）重新安装，装完**重启电脑**，再启动软件。
   - 要客户回报：重启后是否还报 2272。
3. **检查授权服务是否在运行**：任务管理器 → 服务，找到加密狗/授权相关服务
   （名称随产品而定，通常在软件安装说明里标注），确认状态为「正在运行」；
   未运行则启动，再启动软件。
   - 要客户回报：服务名与启动结果。
4. **检查安全软件拦截**：360、火绒、电脑管家、Windows Defender 等可能拦截
   加密狗驱动或授权服务。把软件安装目录与驱动加入白名单/信任区，或在隔离区
   里恢复被拦截的文件，然后重启电脑再试。
   - 要客户回报：安全软件里是否有拦截记录；加白后是否还报 2272。
5. **以上都无效**：判定为加密狗硬件故障或授权文件损坏。
   - 不承诺处理时限，转人工，并在转交摘要里写清：已做过的步骤 + 设备管理器
     中的具体报错项 + 客户机器系统版本。

## 分支 C：客户其实没插加密狗 / 首次安装

追问一句：**软件是刚装的吗？加密狗是在哪买的、有没有做过授权绑定？**

- 没插狗或狗还没发货 → 属于授权发放问题，**不要**让客户继续排查，直接转人工。
- 插着狗但从未激活过 → 按产品激活流程走（需产品手册确认具体步骤）。

## 升级与转人工

出现以下任一情况，直接转人工（handoff），不要继续让客户反复尝试：

- 加密狗在另一台电脑上也不亮（硬件故障 → 换新）。
- 授权服务/驱动重装后仍报 2272（授权文件损坏或需要重新授权）。
- 客户要求换货、退款、批量授权、合同相关事项。

转交摘要（handoff_briefing）请包含：

- `problem_summary`：产品 + 现象 + 错误码 2272 + 加密狗灯状态。
- `unresolved_items`：已试过的步骤（换口/换线/换机/重装驱动/服务/白名单）。
- `suggested_first_reply`：一句话自然话术（不要承诺时限）。

## 排障过程中必须记录的事实

用于写入会话事实卡（facts_card），避免下一位客服重复追问：

- `error_code`：2272（以及客户报的其他错误码）。
- `dongle_led`：亮 / 不亮 / 未知。
- `usb_port_tried`：已试过的端口（是否机箱后置 / 是否经 Hub）。
- `device_manager`：设备管理器里是否出现异常项、具体名称。
- `driver_reinstalled` / `service_running` / `antivirus_blocked`：各步骤结果。

## 话术与节奏约束（来自平台提示词，此处只作提醒）

- 一次只推进一步，**下一步必须等客户反馈后再发**。
- 不要在同一回合把后续步骤连着倒出来。
- 不要向客户解释或猜测系统内部行为（是否重发、排队、超时等）；客户指出收到
  重复或异常消息时，简短承认后直接给下一步。

## 上线到知识库（运维步骤）

本仓只持有知识源文件，Agent 实际检索的是外部 WeKnora 知识库：

1. 复核本文内容（默认分支顺序、服务名、驱动路径需按产品手册确认）。
2. 从支持台「知识库」页上传本文件（`KnowledgeV2` → 上传文件），或调用
   Core 知识代理：`POST /api/v1/knowledge/knowledge-bases/{kbId}/knowledge/file`
   （需管理员身份；见 `core/modules/knowledge-provider/interface/http-routes.ts`）。
3. 上传到 `extension_settings` 里 `support-pipeline.knowledgeConnector` 配的
   `knowledgeBaseIds` 所指的知识库。
4. 验证命中：用一个含「2272 / 加密狗」的测试问题跑一轮，检查该回合的
   `knowledge_retrieved` 回合事件与回喂内容是否就是本文。
