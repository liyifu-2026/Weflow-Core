# Changelog

本文件记录 Client1 对使用者、集成方和开发者有影响的版本变化。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号采用语义化版本。

## [Unreleased]

### Changed

- 应用图标焕新：品牌蓝渐变底板 + 白色对话气泡 + AI 星芒（DiceBear 头像同源的亲和风格）；同步更新 Android 自适应图标（前景/背景/单色）与 favicon、启动图，主屏幕小尺寸下仍保持清晰可辨。
- 联系人黑名单机制上线：联系人卡片可一键拉黑/取消拉黑。拉黑后 AI 不再自动回复、会话从会话列表与隐藏列表移除、不再推送任何通知；消息照常入库，可在联系人页查看历史。卡片同步展示身份徽标（AI 接待中 / 仅人工 / 已拉黑）。
- 联系人卡片信息扩充：新增关键统计（历史会话数、首次联系时间、资料更新时间）与「最近由谁人工处理」，微信原始昵称与共享别名对照展示。
- 本地通知整理：同步过程不再生成本地通知（跨进程推送统一由 Core Expo Push 负责，消除 App 重启后对存量待处理会话的横幅轰炸）；应用角标只统计「需要处理」（待接手 + 转给我），「我处理中」不再计入，角标可正常清零。
- 头像链路对齐平台 DiceBear 预设体系：预设清单经平台代理 URL 渲染（不再内嵌 SVG），与 Console 端同源同脸。
- 「账号与设备」页点击头像改为打开头像选择器（预设 / 相册上传 / 恢复默认），与信息名片页一致，不再直接跳相册。
- 转交选人列表显示客服头像（Core handoff-assignees 新增 avatarUrl 字段）。
- 会话页未读红点修复：Core 投影将 unreadCustomerCount 从 pg 字符串统一转数字，"0" 不再被误判为未读；前端显示条件同步加固。
- 会话内头像数据源兜底：直接进入会话或列表未同步时经 contact-profile 补齐联系人 ID，客户头像可靠显示。
- 会话页加载时轻量刷新用户投影（GET /api/v1/auth/me）：Console 端更换头像/显示名后移动端自动同步，无需重新登录。
- 「人工处理已结束」面板改为主动作按钮「重新接管」（take-over 创建新 cycle），不再呈现为灰色死态。
- 联系人页点击联系人直接进入会话（原有行为），联系人卡片仅在会话内打开，加载失败不再阻断。
- 移除建议回复（智能回复）入口：会话页不再提供 AI 建议生成、采用、依据查看与「建议首句」填入；本地草稿来源统一为人工输入，历史遗留的建议草稿仍可正常打开与编辑。
- 表情包消息改为纯文本展示：`contentType === "emotion"` 的消息直接显示文本字段（`[表情包]<含义>`），不再尝试加载图片。
- 拍一拍消息以系统提示样式居中展示「对方拍了拍你」（`contentType === "pat"`，依赖 Core 通道事件入库支持）。
- 消息时间戳默认隐藏，点击气泡切换显示；时间格式统一为 24 小时制 HH:mm（修复上午/下午颠倒）。
- 会话消息头像与 Console 同源：客户头像经 Core 头像代理按 `contactId` 拉取，人工客服头像使用账号 `avatarUrl`（Console 更换头像后移动端同步），缺失时回退原占位样式。
- 进行中的 Handoff 缺少结构化摘要时展示最小交接视图（标题 + 交接原因），不再出现「暂时不可用」死态；无 Handoff 或已结束的会话不显示交接摘要区域。

### Removed

- 影子验证/复盘反馈入口整体下线：Agent 回复「合适/需复盘」、人工回复「标记本条回复需复盘」与交接摘要「摘要有误」按钮及其 API（`coach/turn-feedback`、`review-feedback`、`brief-feedback`）从移动端移除。

### Fixed

- 发送乐观更新与服务端对账：同一 `clientRequestId` 的服务端回执会替换本地「发送中」消息，实时刷新不再产生重复气泡；发送后消息立即显示在会话流中。
- 解决人工处理后可重新发起：HUMAN_FINISHED 状态下底部不再死锁为「本次人工处理已结束」，改为提供「重新发起会话」入口（调用 take-over 创建新 cycle）；takeOver 守卫同步放行 finished 状态。

### Added

- 增加「信息名片」页面：客服可自助更换头像、编辑显示名（1-24 字符，清空回落为登录账号）、多选擅长领域标签（标签词表来自 Server2 专家队列，上限 7 个），并从名片进入修改密码；旧 Server2 无 `agentProfile` 能力时隐藏资料编辑区。
- 客服显示名（`displayName`）优先于登录账号展示：Inbox 顶栏头像字母、人工消息头像字母、账号与设备页与名片页均采用显示名；转交列表由 Server2 返回新字段。
- 修改密码页支持从名片自愿进入：非首次登录场景显示返回头、成功后返回上一页，不再强制进入工作台或提供退出登录。
- 增加由 Server2 capability 开关控制的 Mobile Handoff 新合同：专用 Inbox、独立 `conversationRevision` / `handoffRevision`、Structured Brief、转交周期、人工结果推断与请求 outcome 查询。
- 增加统一“转交处理”流程：可转给具体客服或专业队列，共用 Server2 生成的结构化交接确认页和必填短原因。
- 增加指定客服转交的接受、拒绝和 fallback 状态；原负责人转交成功后立即进入只读。
- 增加离线 owner 本机草稿编辑；离线时禁止发送、接手、转交、结束人工处理和建议生成。
- 增加结束后的 Server2 异步 `resolutionSummary` 与受控 Human → Agent 上下文，只继承处理结果、总结、最终事实、未解决事项和必要客户约束。
- 增加弱化的 Brief“摘要有误”和人工消息“需复盘”质量反馈入口。
- 增加「Agent 处理中」分区：capability `mobileManualTakeover` 开启时，Inbox 第三档列出 Server2 判定可主动接管的 AGENT_ACTIVE 会话，可一键接管（Manual Takeover）。
- 主动接管为服务端原子操作（`manual_taken_over`）：接管后 Agent 暂停、进入既有人工链路；幂等 `clientRequestId` 支持安全重试，竞争失败自动刷新为服务端事实，结果未知可经 `take_over` outcome 查询确认。

### Changed

- 重构为单一 Agent → Human → Agent 移动工作台：移除底部导航和独立知识、待办、隐藏会话入口，登录后只进入“人工接管” Inbox。
- Inbox 只显示“等待接手 / 我处理中”，保留 Server2 业务排序；搜索默认收起，会话行只呈现联系人、问题、人工介入原因和等待时间。
- Inbox 分区扩展为“等待接手 / 我处理中 / Agent 处理中”（第三档由 `mobileManualTakeover` capability 门控）；Agent 处理中会话详情底部由“当前由 Agent 处理”只读提示升级为“接管处理”主操作。
- 待接手详情只显示 Structured Brief、Transcript 和唯一主操作“接手处理”；接手后 Composer 自然出现，不自动弹出键盘。
- 建议回复改为 Server2 revision 绑定对象；过期建议只能重新生成，采用后才变为 Human Draft，永不自动发送。
- 指定客服转交采用 Server2 给出的 15 分钟 `acceptBy` 与 `fallbackQueueId`；拒绝或超时不退回原客服，也不恢复 Agent。
- 建议入口收敛为生成、采用、依据和重新生成；移除会话内的查询工作台、上下文覆盖和完整结果入口。
- 会话完成统一改为“结束人工处理”，明确表达后续新客户消息将重新由 Agent 处理，不表示永久关闭会话。
- 登录与后台隐私遮罩统一为 `Weflow / 人工接管`语义；版本信息改为从 Expo 单一配置源读取。
- 视觉收敛为暖中性画布、深墨文字和单一克制蓝灰强调，主要依靠排版、间距和分隔线建立层级。

### Fixed

- Handoff 请求失败不再被误判为“没有 Handoff”；Transcript 可继续显示，责任操作区单独进入只读。
- 无有效 Handoff 时不再隐式提供主动接手或回复权限。
- `mobileHandoffInbox` capability 缺失时不再读取普通 Conversation 并在客户端过滤出伪 Inbox，而是明确显示能力未开放。
- 待接手状态不再运行用户不可见的 Suggestion pipeline；先接手，再由人工生成建议。
- 领取冲突改为直接刷新 Server2 真实归属并进入只读，不再弹出错误 Alert。
- 消息、Handoff、Suggestion 和图片失败按能力局部隔离，避免单一错误使整个工作页失效。
- 结果未知的人工消息在本地安全存储中保留原 `clientRequestId` 和 conversation revision；应用重启后仍会先查询原请求结果，并持续阻止转交、结束和重复发送。
- ownership 或 Cycle 在其他端发生变化时，未发送本机草稿改为只读归档；可查看或复制，但不能跨 Cycle 发送。

### Removed

- 停止创建新的 Assist Request；存量请求仅保留查看、提交意见、关闭和取消。
- 移除独立知识工作台、待办中心、隐藏会话和底部导航入口。

### Security

- Preview / Production 构建强制使用 HTTPS Server2；明文 HTTP 仅在 Development 且显式开启时允许。
- Brief 与 Transcript 只在同一 `conversationRevision` 下共同缓存；本地草稿继续按账号和 Handoff Cycle 隔离。

## [0.7.0] - 2026-08-04

### Added

- 知识页改为“浏览优先的资料库”：进入即浏览全部知识库文档与 FAQ，按知识库分组、标签子类筛选；新增最近使用与收藏（按账号本地保存）；搜索框支持本地输入联想（资料标题与 FAQ 问题前缀匹配，不触发完整检索）；文档全文支持 Markdown 渲染阅读；搜索结果按 FAQ 标准答案 → 相关资料 → AI 整理建议 → 继续提问的顺序原地浮现，AI 整理区域使用液态玻璃卡片。
- Server2 新增知识库目录端点 `GET /api/v1/knowledge/library`（知识库 + 文档元数据 + 标签 + FAQ 条目聚合）与文档全文端点 `GET /api/v1/knowledge/documents/:documentId/content`（WeKnora chunks 拼接，超长截断）；客户端新增 `src/knowledge/library-*` 模块与 `react-native-markdown-display` 依赖。
- 知识驾驶舱支持全库探索与当前会话模式：会话上下文胶囊、会话专属知识线程、会话级证据托盘、结构化建议回复/追问/排查步骤/风险提醒和知识反馈事件；建议回复仍只进入负责人安全草稿，不会自动发送。
- 新增独立知识工作台：支持跨资料搜索、证据片段、知识助手问答和受保护的原文摘要查看；现有会话内 AI 辅助行为保持不变。
- 知识历史按范围分组：全库探索只显示独立查询，当前会话只显示本会话查询并带联系人与会话状态；历史线程可一键恢复到工作区（问题、知识范围、证据托盘、上下文覆盖层与结构化建议），会话已有新消息时提示重新检查后再用。
- 会话上下文覆盖层编辑：知识页与半屏知识辅助可修改产品、错误码、已确认事实、已尝试步骤和缺失信息，并可选择是否包含最近消息；覆盖层只用于本次查询，不写回客户档案。
- 会话搜索扩展为服务端历史消息搜索；对话支持按当前账号隐藏、恢复，原始业务数据仍保留。
- 登录页移除装饰性插图，仅保留产品名和登录表单；账号页支持跟随系统、浅色和深色三种主题模式。
- 新增抽象几何 SVG 插图系统：登录页大视觉与会话、待办、知识、详情的空状态统一使用“重复平移几何模块 + 柔和渐变”的轻量矢量图，浅深主题自动适配。
- 新增自动 AI 辅助：客户发来知识型问题（错误码 / 型号 / 故障关键词，或待判断会话）后由客户端本地启发式自动触发静默检索；会话输入区上方浮现液态玻璃建议条（采用 / 查看依据 / 展开），采用后写入安全草稿并由客服确认发送，任何路径都不会自动发送消息；完整知识驾驶舱保留为高级层，经建议条“···”或“＋ → AI 辅助”进入。
- 新增本地触发模块与建议状态机：错误码/型号/故障词启发式、冷却与消息去重、generationId 丢弃过期流（流式接口不支持取消）；新增 SVG 渐变玻璃卡片组件，无新增依赖，浅深两套配色。

### Changed

- 知识页顶部搜索框成为唯一搜索入口：回车或放大镜触发，支持清空；移除右上角“检索”按钮、空态“从一个问题开始”大卡片与“全部知识库/查询范围”常驻说明；清除搜索后回到原浏览位置，浏览列表不卸载。
- 会话上下文模式改为轻量上下文条：进入知识页仍可自由浏览全部资料，搜索与生成自动携带当前会话覆盖层和最近消息，依据可在 AI 整理卡片内查看；不再默认常驻“本次处理依据”证据托盘。
- 知识证据托盘从客户端移除（`getKnowledgeEvidenceTray` / `updateKnowledgeEvidenceTray` 与托盘 UI 删除）；Server2 对应端点保留，不影响既有数据。
- 会话详情“＋”菜单将“AI 建议回复 / 搜索内部知识”两项合并为“AI 辅助”；删除旧 `KnowledgePanel` 与 `IntelligentProgress` 死代码及检索死桩。
- 自动建议与现有建议胶囊 / `stale_revision` 机制衔接：新客户消息后建议条标记“会话已有新内容”并触发重新分析；已采用草稿仍由会话 revision 闸门阻止过期发送。
- 知识证据托盘改为只提交 `knowledgeId` / `chunkId`；Server2 会重新校验当前可访问资料并保存带内容哈希的服务端快照。选择“根据本次处理依据回答”时，生成模型只接收已校验快照，不再使用全库自由检索；流式生成同时补齐失败终态和断线后的生成锁清理。
- 重构移动客服工作台 UI：一级页面改为单一任务结构，个人入口改为底部面板，会话行收敛为联系人、摘要、状态和未读信息，隐藏会话支持左滑，待办改为行动队列，知识页改为“资料检索 / 知识助手”双模式。
- 会话详情减少常驻操作，交接摘要改为底部摘要面板，知识、协助、转交和完成收纳到更多操作；登录页不再维护主题插图资源。
- 会话和待办列表改用 `FlatList` / `SectionList` 虚拟化渲染，保留下拉刷新、错误和空状态；会话筛选改为临时选择并点击“应用”后生效。
- 登录页增加键盘避让、可滚动表单和密码显示/隐藏控制；知识文档预览改为标题固定、正文独立滚动的弹层。
- 简化账号与设备页：主页面只保留偏好和数据入口，缓存与版本信息移至安全与关于；通知与隐私页改为轻量设置层级并提升辅助文字可读性。
- 统一会话、待办和知识页的加载、失败与空状态；知识文档预览区分当前匹配和受保护原文内容。原文件转发仍等待 Server2 提供文件消息发送合同。
- 后台同步不再强制重排正在查看的会话；新消息和状态变化先保留当前顺序并显示刷新提示，手动刷新后才应用最新关注度排序；补充关键列表、筛选和模式控件的无障碍语义。
- 建立统一布局、触控尺寸和字号 token，并用于核心工作页、设置页和认证页；首次改密页面也支持键盘避让和辅助状态。
- 精简登录、账号与设备、知识入口的说明性文案，把安全说明移至独立的“安全与关于”页面。
- Client1 与 Server2 知识工作台契约增加受保护文档摘要和预览代理；WeKnora API Key 只由 Server2 运行时密钥配置持有，客户端不接触。
- Client1 知识页重构为统一证据优先工作台：支持按知识库范围查询、按文件聚合来源、生成可编辑建议、复制回答和受保护原文预览；Server2 不再向客户端暴露检索分数。
- 知识建议生成接入 Server2 代理的 WeKnora SSE 流；回答按片段渐进显示，支持停止生成，停止请求按客服账号隔离，且上游引用和会话标识不会暴露给 Client1。
- 知识工作台增加账号隔离的历史线程和回答后推荐追问；推荐问题只继续当前知识线程，不自动发送客户消息，WeKnora 会话 ID 仍仅由 Server2 保存。
- Client1 与 Server2 知识合同增加会话上下文、证据托盘、结构化 SSE 行动输出和反馈记录；Server2 新增 `0030_client1_knowledge_cockpit` 迁移。
- Server2 知识线程列表 `GET /api/v1/knowledge/threads` 支持 `scopeType` / `scopeId` 过滤，并为会话线程返回联系人与 Handoff 状态；线程消息新增 `metadata` 字段保存查询选项、行动输出与生成时会话 revision，新增迁移 `0031_client1_knowledge_thread_metadata`。
- 知识流式回答的 `contextOverride` 合同扩展 `product` / `errorCode` / `triedSteps`，并支持 `includeRecentMessages`；全库检索与选中证据两条生成路径共用同一覆盖层应用逻辑，覆盖层不写回 Case State。
- 草稿存储拆分可注入核心（存储与摘要算法可替换，测试不引入真实 SecureStore），草稿生命周期决策（加载后状态、发送闸门、失败恢复、转交可见性）抽为独立模块并补齐页面级行为测试。

### Security

- Token 仅使用 Expo SecureStore 持久化；API 请求使用 HTTPS Bearer Token。
- 切换账号时通过 Server2 撤销当前设备推送 Token，避免退出后继续接收旧账号的移动通知。
- 内网开发包临时允许访问 `http://192.168.10.175:3100`；发布前必须恢复 HTTPS 并关闭 cleartext traffic。
